# BH-RESEARCH-SYNC | MT-WEB-28 — Publication Boundary v0.1

Status: `DENY_ALL_LOCAL_BOUNDARY`.

The first relevant scientific publication, verified provenance and a distinct
human authorization are prerequisites for considering public automatic registry
activation. They do not, by themselves, activate it. During laboratory
qualification, candidates and their projections remain internal.

The `publication_boundary.py` module invokes the deny-by-default gate before
any attempted public output. The writer remains deliberately unimplemented.
This avoids mistaking a guarded prototype for a complete production publisher.

**This gate only governs calls routed through this new boundary.** Existing
unrelated manual publishing workflows, Git pushes, Vercel deployments and any
future publication code do not automatically become covered. A future mission
must enumerate and mediate every entrypoint, enforce source/provenance policy,
qualify recovery and verify adversarial bypass attempts before claiming global
enforcement.

No scientific result is created, classified as qualified or published by this
mission. No commit, push or deployment is executed.
